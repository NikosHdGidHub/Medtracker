# Тестирование

## Автоматические проверки

Требуются Node.js 24, npm, Java 25, свободные локальные порты 8080, 9099 и 5174. Firebase CLI скачивает официальный Firestore Emulator с `storage.googleapis.com`, Playwright скачивает браузер при установке.

```bash
npm ci
npm run typecheck
npm run lint
npm test
npm run test:rules
npx playwright install chromium
npm run test:e2e
npm run build
```

- Модульные тесты покрывают дневной и недельный план, границу дня, переход дедлайна через полночь, DST, временные версии, паузу, завершение, отчёты, компенсации и шаги напоминаний.
- Тесты Firestore Emulator проверяют запрещённый доступ, изоляцию UID, валидацию, конкурентное подтверждение, остаток, журнал, версии и поведение при отключении сети.
- Playwright проверяет регистрацию, допуск, ежедневную отметку с подтверждением на другом сеансе, исправление, старый месяц, экспорт CSV, встроенное уведомление, выход и вызов восстановления пароля. Auth Emulator не доставляет настоящее письмо.
- Локальная проверка статической сборки `npm run test:production` запускается после `npm run build`, собранного без Firebase-конфигурации. Она проверяет кэш оболочки и навигацию по hash на эмулированном телефоне. Для системного Chromium можно задать `MEDTRACKER_CHROMIUM=/path/to/chromium`.

Если вы уже запустили официальные эмуляторы вручную, можно использовать существующие процессы:

```bash
FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 npx vitest run tests/firestore.test.ts
FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 npx playwright test --project tracker
```

Используйте выделенный проект `demo-medtracker`: набор Firestore очищает тестовую базу между сценариями.

## Локальный запуск с эмуляторами

В одном терминале запустите `npm run emulators`. Во втором выполните:

```bash
VITE_USE_FIREBASE_EMULATORS=true npm run dev
```

Зарегистрируйте синтетический аккаунт и скопируйте UID со страницы ожидания. В локальном Firestore Emulator добавьте документ `access/{UID}` с `enabled: true` через Emulator UI или тестовый административный сценарий. Для UI можно временно включить `emulators.ui.enabled` в локальной копии `firebase.json` и перезапустить эмуляторы. Результаты автономного теста можно получить без ручного добавления через `npm run test:e2e`, который сам выдаёт допуск тестовому аккаунту. Production-сборка игнорирует флаг локального эмулятора.

## Ручная приёмка после развёртывания

1. В новом профиле браузера проверьте регистрацию, допуск, выход, повторный вход и восстановление пароля через фактическое письмо.
2. С двумя допущенными тестовыми аккаунтами проверьте, что история и запасы не пересекаются. Отзовите допуск в активной вкладке.
3. Добавьте ежедневный слот, ночной слот 01:30 и выбранные дни недели. Проверьте дедлайн после 04:00 и старые месяцы после смены расписания.
4. Подтвердите один приём в двух вкладках. Проверьте одно списание. Исправьте количество и время, затем отмените отметку и проверьте компенсацию.
5. Установите короткий тестовый дедлайн и оставьте вкладку открытой. Проверьте повторы, прекращение после явного пропуска и fallback при запрещённом разрешении.
6. На физическом Android откройте сайт в Chrome, установите PWA и проверьте узкий экран, повторное открытие, системное уведомление и потерю связи. При отключении интернета изменения не должны считаться сохранёнными.
7. Проверьте CSV, JSON и ручную процедуру удаления на выделенном тестовом аккаунте. Рабочие записи для проверки не требуются.
