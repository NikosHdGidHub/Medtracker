# Публикация на GitHub Pages

Целевой адрес — [nikoshdgidhub.github.io/Medtracker/](https://nikoshdgidhub.github.io/Medtracker/). Сборка ничего не размещает на Firebase Hosting. Auth и Firestore остаются отдельными сервисами Firebase.

## Настройка GitHub

1. Настройте Firebase по инструкции и добавьте `nikoshdgidhub.github.io` в Authorized domains. Не подключайте рабочие медицинские данные, пока не оцените ограничения ниже.
2. В репозитории откройте «Settings → Actions → General» и разрешите официальные GitHub Actions. Workflow использует права чтения исходного кода, права `pages: write` и `id-token: write` для задания развёртывания.
3. В «Settings → Secrets and variables → Actions → Variables» добавьте `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`, при наличии `VITE_FIREBASE_MESSAGING_SENDER_ID`, а также `VITE_ALLOW_REGISTRATION` со значением `true` или `false`. Эти значения входят в публичную сборку.
4. В «Settings → Pages → Build and deployment» выберите Source «GitHub Actions». Проверьте, что план репозитория поддерживает Pages с выбранной видимостью. После первого запуска проверьте правила среды `github-pages`, если в организации настроены подтверждения развёртывания.

## Первая публикация и обновления

Слейте проверенную ветку в `main` или запустите «Build and deploy Medtracker» вручную с ветки `main` на вкладке Actions. Успешный workflow проверит типы, lint, модульные и эмуляторные тесты, соберёт `dist` и передаст артефакт заданию Deploy. Для pull request запускаются проверки без публикации. При каждом последующем push в `main` сборка обновит Pages. Изменение Actions Variables требует нового запуска сборки.

Откройте адрес Pages. В DevTools проверьте 200 для HTML, JS, CSS, манифеста, иконок и Service Worker. Перейдите в «История» и обновите страницу на hash-маршруте. Проверьте регистрацию или вход по email и паролю, загрузку допуска и создание тестовой записи. В Application проверьте область Service Worker `/Medtracker/`. При обновлении сборки новый Service Worker загружает новый набор статических файлов. Открытая страница обновляет интерфейс при следующей загрузке.

## Ограничения хостинга

GitHub прямо предупреждает, что сайты GitHub Pages не следует использовать для чувствительных транзакций, включая отправку паролей. В этой конфигурации поля входа отображаются в коде, размещённом на Pages, а браузер отправляет учётные данные и записи по TLS напрямую Firebase. Сайт на Pages всё равно является источником кода формы входа и может быть заменён при компрометации доступа к публикации. Разделение сервисов не отменяет предупреждение GitHub. До использования схемы с реальными данными владельцу нужно оценить применимость правил площадки и требования к защите чувствительных данных. Проверку публикации можно провести на синтетических аккаунтах и записях. [Официальные ограничения GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

В Git и артефакты Pages включаются код, статические ресурсы и публичная конфигурация Firebase. Пароли, экспорты, рабочие документы Firestore и административные ключи хранятся отдельно.
